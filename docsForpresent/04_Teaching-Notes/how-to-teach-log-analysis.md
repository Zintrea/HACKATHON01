# How To Teach Log Analysis — วิธีสอนคนอื่นให้เข้าใจ

## Sequence การสอนที่แนะนำ

### 1. เริ่มจากโจทย์

ถามทีม:

```text
ถ้าเราเป็นคนดูแลเว็บ แล้วเว็บล่ม เราต้องรู้อะไรบ้าง?
```

คำตอบที่อยากได้:

- ใครทำ
- ทำตอนไหน
- ทำยังไง
- ระบบเสียหายแค่ไหน
- จะแสดงให้คนอื่นเข้าใจยังไง

### 2. อธิบาย log format

ให้ดูตัวอย่างหนึ่งบรรทัด:

```text
time | ip | method | path | status | size
```

บอกว่า:

```text
นี่คือหลักฐานดิบ เหมือนใบเสร็จของทุก request
```

### 3. สอน red flags

ใช้ 4 หมวดพอ:

- payload แปลก
- status แปลก
- rate แปลก
- endpoint แปลก

### 4. สอนว่าทำไมต้อง aggregate

หนึ่งบรรทัดอาจหลอก แต่ aggregate เห็น pattern

```text
บรรทัดเดียว = clue
หลายร้อยบรรทัดจาก IP เดียว = behavior
behavior ตรงช่วงระบบพัง = evidence
```

### 5. สอน scoring

อธิบายว่าเราให้คะแนนเพื่อจัดลำดับ ไม่ใช่ตัดสินมั่ว

### 6. สอน Dashboard

Dashboard คือการเล่า incident ให้คนที่ไม่อ่าน log เข้าใจ

## Mini Example สำหรับสอน

```text
09:00 | 1.1.1.1 | GET | /products | 200
09:01 | 2.2.2.2 | GET | /.env | 404
09:01 | 2.2.2.2 | GET | /config.php | 404
09:02 | 2.2.2.2 | GET | /search?q='OR 1=1 | 500
```

ถามทีม:

1. IP ไหนน่าสงสัย?
2. ทำไม?
3. red flags มีอะไร?
4. ถ้าเอาไป dashboard จะแสดงอะไร?

## ข้อควรสอนให้จำ

- อย่าเชื่อ request เดียว
- อย่าใช้ status code อย่างเดียว
- อย่าพูดเกิน field ที่ log มี
- ต้องเก็บ evidence เสมอ
- hidden clue อาจไม่ตรงไปตรงมา
